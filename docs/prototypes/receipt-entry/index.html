Entering a Receipt: does the model hold up?

The question. We decided how a Receipt works: Line items with a unit price and quantity, an optional Line discount, a deposit per unit that follows the Line item's split, Deposit refunds as negative lines, a Receipt discount, Contributions, and Receipts left incomplete to split later. Push real shop situations through it. Is anything awkward, surprising, or allowed when it shouldn't be? Is it fast to enter at the till?

Assumption: this is the logic prototype. It checks the rules and the order you enter things in, not the screen layout. Layout options are in Which Receipt entry layout works best on a phone?

Proposals to react to (not decided yet): a new Line item copies the previous Line item's split if that split was Even, otherwise it starts Even across everyone. Switching a line's Split mode starts that mode from scratch. Amounts accept 0,29, ,29, .29 and 1.234,50: the last separator is always the decimal one.

Use the walkthroughs at the bottom, or the free-play controls, in any order. Every amount is kept exact; cents appear only on screen, and ≈ marks a rounded value.
